What SAJHA is

SAJHA turns a catalog of data and utility tools (market data, central banks, public statistics, filings, search, analytics, calculators) and reusable prompts into something any MCP client can discover and call: an AI assistant, an agent framework or a script.

Around that core it adds what running such a server needs: a web console, users and roles, API keys, OAuth 2.1 on /mcp, a sandbox for user code, a visual tool builder, tool composition, federation of other MCP servers, an intelligence layer that answers questions with the tools, caching, circuit breakers, observability, shared state for several workers and pluggable storage. The name

Protocol

One /mcp endpoint serves both eras, chosen per request:

  • Stateless ({{ modern_versions|join(', ') }}): no handshake and no session; every request is complete in itself.
  • Session-based ({{ handshake_versions|join(', ') }}): initialize first, then requests on the session.

How it works: the MCP Protocol Guide. What was tested, with the conformance-suite results and known limits: 2026-07-28 and 2025-11-25 compliance reports.

Access
  • SAJHA's own credentials: a login session, a SAJHA JWT, or an API key limited to the tools it may call. Roles decide what each account can do in the console.
  • OAuth 2.1 on /mcp, set by mcp.auth.mode: off (the default), optional or required; tokens from the built-in authorization server or an external issuer.
  • OAuth here is not single sign-on for the web console, and SAJHA is not an OpenID Connect provider.
