Planner editor

Planners decide how an LLM tool answers: which stages run, how often a loop may repeat and what it may spend. Edit a planner file, check it against the schema and the P-rules, see its graph, dry-run it on the mock model, and save it as a new version. Administrators only.

    Versions and the last good file

    {{ planner_data.dir }}/<name>.yaml holds the newest version; saving a new version keeps the one it replaces as <name>@<version>.yaml, so tools that pin name@version keep what they were tested with. A version cannot be saved twice with different content: change version.

    The editor never writes a file that fails validation. If a file edited elsewhere fails, the registry keeps the last good version of that name@version in use, logs the error and counts it (sajha_planner_load_errors_total); running tools keep working, and the problem is listed above.
