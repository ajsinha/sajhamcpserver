# Calendars Tool Reference Guide

The calendars tools (prefix `cal_`, tool folder `config/tools/calendars/`, implementation
`sajha/tools/impl/calendars_tools.py`) answer holiday and business-day questions: is this date a
business day in New York and Toronto, what is the settlement date of a T+1 trade, how many business
days lie between two dates. The live catalog (`tools/list`, or the Tools page) is authoritative for
the tools and their parameters; the table below is generated from the tool configs.

Why these tools exist, and on what terms, is in
[Open Data Tools](../../architecture/Open%20Data%20Tools.md).

---

## Source and terms

Everything is computed **offline** from the rules of the [`holidays`](https://github.com/vacanza/holidays)
Python package (MIT licence). No request leaves the server and no key is needed, so the tools carry
`openWorldHint: false`. Every result names the package in its `source` field.

`holidays` is an optional dependency: each tool config declares `"requires": ["holidays"]`. While the
package is not installed the tools are not loaded, and the info notice `tools.requires:holidays` says
so. Install it into SAJHA's Python environment (it is listed in `requirements.txt`) to enable them.

The rules are the package's. A one-off closure (a national day of mourning, for example) appears only
once the package's maintainers add it, so keep the package current. The rules are what an exchange or
government has announced; they are not a promise that a market will open.

## Calendar codes

Every tool takes calendar codes in one form:

| Form | Example | Meaning |
|---|---|---|
| ISO 3166 country, alpha-2 or alpha-3 | `US`, `CA`, `GBR` | The country's public holidays |
| Country and subdivision | `CA-ON`, `US-NY` | Public holidays of that province or state |
| ISO 10383 market identifier code | `XNYS`, `XNAS`, `XLON`, `XTSE`, `XECB` | The exchange's trading holidays (`XECB` is the TARGET2 calendar) |
| A market alias the package knows | `NYSE`, `LSE`, `TSX` | The same as its market code |

`cal_holidays` takes `country` (with an optional `subdivision`) or `market` separately; the other tools
take a list, `calendars`. With several calendars a day is a business day only when it is one in **all**
of them, which is what a cross-border trade needs (for example `["XNYS", "CA"]`).

Weekends follow each calendar's own convention (Saturday and Sunday for most). A country's holiday
rules include observed days (a holiday falling on a weekend moved to a weekday) where the country
observes them.

## Conventions

- **Dates** are `YYYY-MM-DD` in and out.
- **Counting** (`cal_business_days_between`): the start date is counted, the end date is not, like a
  day count; the answer is negative when `to` is before `from`. `holidays_on_weekdays` lists the
  holidays that removed a working day in the range.
- **Adding** (`cal_add_business_days`): `days` business days after the date (before it when negative).
  With `days: 0` the answer is the date itself when it is a business day, otherwise the next one.
- **Settlement** (`cal_settlement_date`): `T+n` is the trade date plus `n` business days; `T+0` rolls a
  non-business trade date to the next business day. `trade_date_is_business_day` flags a trade date
  that is not one.
- **Adjusting** (`cal_adjust_date`): `following` moves to the next business day, `preceding` to the
  previous one, and `modified_following` moves forward unless that leaves the month, in which case it
  moves back.

## Examples

```json
{"tool": "cal_is_business_day", "arguments": {"date": "2026-11-26", "calendars": ["XNYS", "CA"]}}
```

Thanksgiving: `is_business_day` is false, and the per-calendar detail shows `XNYS` closed for
"Thanksgiving Day" while `CA` is open.

```json
{"tool": "cal_adjust_date", "arguments": {"date": "2026-10-31", "rule": "modified_following", "calendars": ["XLON"]}}
```

31 October 2026 is a Saturday. Following would give 2 November, which leaves the month, so modified
following gives Friday 30 October.
