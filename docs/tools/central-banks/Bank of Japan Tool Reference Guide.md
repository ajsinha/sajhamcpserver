## Overview

The Bank of Japan tools (prefix `boj_`) return Japanese government bond and money-market rates, the BoJ's call-rate target, yen exchange rates, broad money, consumer prices and macro indicators. Implementation: `sajha/tools/impl/japan_central_bank.py` on the shared base `sajha/tools/impl/central_bank_series.py`. The live catalog in the app (Tools page, or `tools/list`) is authoritative.

The tools do **not** call the Bank of Japan's Time-Series Data Search. Each series comes from one of two open sources, named in every result's `source`: the St. Louis Fed's [FRED](https://fred.stlouisfed.org/) (OECD and BoJ series republished), or the IMF's SDMX API (`api.imf.org`) through SAJHA's shared SDMX client. Every series id was checked live. FRED's Japanese discount rate and M1/M2 ended in 2017, its M3 in 2023, its CPI in 2021 and its industrial production in 2024, and its PPI is gone, so those are not offered; CPI and broad money come from the IMF instead.

---

## Data Source and API Key

FRED-backed series need a free FRED API key ([fred.stlouisfed.org](https://fred.stlouisfed.org/docs/api/api_key.html)): `FRED_API_KEY`, config key `fred.api.key` (see the [Configuration Reference](../../getting-started/Configuration%20Reference.md)). Each `boj_` config carries `"api_key": "${fred.api.key}"`, and the tools fall back to the environment variable (one lookup for every FRED-backed tool: `sajha/tools/impl/fred_key.py`). Without a key a FRED-backed call fails with "FRED API key not configured"; it never returns invented values. IMF-backed series (`broad_money`, `cpi`, `cpi_inflation`) and `boj_list_series` need no key.

### Common parameters (all data tools)

| Parameter | Type | Description |
|-----------|------|-------------|
| `start_date` | string | Start date, `YYYY-MM-DD` |
| `end_date` | string | End date, `YYYY-MM-DD` |
| `recent_periods` | integer | The last N observations (default 10); used only when neither date is given. With a date, the whole range is returned. |

No argument is required; each tool's choice argument defaults to the first value below.

## Response Format

```json
{
  "series_code": "XTNTVA01JPM664S",
  "series_id": "trade_balance",
  "label": "Goods trade balance (exports less imports), yen, monthly, seasonally adjusted (OECD)",
  "source": "FRED (Federal Reserve Bank of St. Louis)",
  "observation_count": 10,
  "observations": [{"date": "2026-06-01", "value": -881932000000.0}]
}
```

`series_code` is the FRED id, or the IMF dataflow and key. Observations are oldest first; missing values are dropped. `eur_jpy` also carries `units`. An unsupported argument value or an upstream failure is a tool error.

## Calling the Tools

Every tool can be called over MCP (a `tools/call` request on `POST /mcp`) or over the REST API (`POST /api/tools/execute`). Authenticate with an `X-API-Key: sja_...` header or an `Authorization: Bearer <token>` header. Sessions, protocol versions and headers are covered in the [MCP Protocol Guide](../../protocol/MCP%20Protocol%20Guide.md).

**MCP (`POST /mcp`)**

```json
{"jsonrpc": "2.0", "id": 1, "method": "tools/call",
 "params": {"name": "boj_get_inflation", "arguments": {"index_type": "cpi_inflation", "recent_periods": 12}}}
```

**REST**

```bash
curl -X POST http://localhost:3002/api/tools/execute \
  -H "X-API-Key: sja_your_key" -H "Content-Type: application/json" \
  -d '{"tool": "boj_get_inflation", "arguments": {"index_type": "cpi_inflation", "recent_periods": 12}}'
```

**Python client SDK**

```python
from sajhaclient import SajhaClient, SajhaConfig

client = SajhaClient(SajhaConfig(base_url="http://localhost:3002", api_key="sja_your_key"))
result = client.execute_tool("boj_get_inflation", index_type="cpi_inflation", recent_periods=12)
```

## Troubleshooting

| Symptom | Cause / fix |
|---------|-------------|
| "FRED API key not configured" | Set `FRED_API_KEY` (see [Data Source and API Key](#data-source-and-api-key)). |
| `Unsupported ...` error | The value is outside what the implementation accepts (tables above). |
| `FRED has no series ...` / `IMF data portal: ...` | The upstream rejected the request; check dates are `YYYY-MM-DD`. IMF monthly data lag official releases by some months. |
| Empty `observations` | No data in the requested range; widen the dates or use `recent_periods`. |
