# GDELT Tool Reference Guide

The GDELT tools (prefix `gdelt_`, tool folder `config/tools/gdelt/`, implementation
`sajha/tools/impl/gdelt_tools.py`) read the GDELT Project's news monitoring: articles worldwide, how
much coverage a topic gets and its tone, and sentences in context. The live
catalog (`tools/list`, or the Tools page) is authoritative for the tools and their parameters; the
table below is generated from the tool configs.

Why these tools exist, and on what terms, is in
[Open Data Tools](../../architecture/Open%20Data%20Tools.md).

---

## Source and terms

The source is `https://api.gdeltproject.org/api/v2/`: the DOC 2.0 (`doc/doc`) and Context 2.0
(`context/context`) APIs. No key. GDELT's terms allow unlimited use, commercial included,
provided any use or redistribution cites the GDELT Project and links to https://www.gdeltproject.org/;
every result carries that citation in its `source` field. Two GDELT APIs are not offered: GEO 2.0
answers 404, and TV 2.0 (television news mentions, from the Internet Archive's TV News Archive) answers
but has held no data since October 2024 (checked 2026-10-12). Every
request goes through the outbound fetch guard and HTTP proxy (`sajha/core/outbound.py`).

## Rate limit and cache

GDELT allows one request every 5 seconds (stated only in its 429 message), and the whole organisation
shares that behind its egress IP. So:

- **Throttle.** Every request first takes the one slot in a 5-second window in the state store (key
  `opendata:gdelt:requests`), shared by every worker when the state store is `redis` or `database`
  ([Scaling and State](../../architecture/Scaling%20and%20State.md)). A call waits up to 30 seconds for
  the slot, then fails with a message saying the budget is busy. A 429 answer is retried once, in the
  next slot.
- **Cache.** Each tool config sets `cache_ttl` (an hour; 30 minutes for `gdelt_context`).
- GDELT answers 429 often even at its stated pace: on 2026-10-12 the DOC API refused calls seconds
  apart and sometimes a minute apart (the Context API did not). Expect waits and an occasional
  rate-limit error. The live tool check spaces the `gdelt_` tools a minute apart (`check_pause_seconds`).

## Conventions

- **Queries** use GDELT's syntax: words, `"exact phrases"`, `(a OR b)` and `-excluded`. Very short or
  very common words are refused by GDELT; the error says so.
- **Dates** are `YYYY-MM-DD` (UTC), at most 92 days per DOC call. Without dates, `gdelt_articles` reads
  the last 7 days and `gdelt_coverage_timeline` the last 30. `gdelt_context`
  covers about the last 72 hours.
- **Filters.** `source_country`, `language` and `domain` add GDELT's `sourcecountry:`, `sourcelang:` and
  `domain:` operators.
- **Units.** `volume` is the percent of all articles GDELT monitored in each interval; `article_count`
  the matching article count (with `total`, all articles monitored); `tone` the average tone, about -10
  (very negative) to +10 (very positive). Each result states its units.

## Examples

```json
{"tool": "gdelt_coverage_timeline", "arguments": {"query": "\"bank failure\"", "measure": "tone", "from": "2026-09-01", "to": "2026-09-30"}}
```

```json
{"tool": "gdelt_articles", "arguments": {"query": "\"interest rates\"", "source_country": "UK", "max_records": 10}}
```

## Testing

`tests/test_open_data_p3.py` plays back responses recorded live (`tests/fixtures/open_data/gdelt_*.json`)
and checks the throttle and the 429 retry, so the suite never calls GDELT. Each tool has a probe case and
a cassette in `config/tool_tests/`. The live tool check is
`python -m sajha.quality check --folder gdelt`.
