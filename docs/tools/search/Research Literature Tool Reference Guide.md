# Research Literature Tool Reference Guide

The research tools (prefix `research_`, tool folder `config/tools/research/`, implementation
`sajha/tools/impl/research_tools.py`) find scholarly literature: works and citations from OpenAlex,
bibliographic records from Crossref, and preprints from arXiv. The live catalog (`tools/list`, or the
Tools page) is authoritative for the tools and their parameters; the table below is generated from the
tool configs.

Why these tools exist, and on what terms, is in
[Open Data Tools](../../architecture/Open%20Data%20Tools.md).

---

## Sources and terms

| Source | Endpoint | Key | Terms and limits |
|---|---|---|---|
| OpenAlex | `https://api.openalex.org/` | optional: a free key in `OPENALEX_API_KEY`, sent as `api_key` | CC0. Usage-priced: about US$0.10 a day per IP without a key, US$1 a day with a free key (resets at midnight UTC). A list call cost US$0.001 when checked (filter or search alike); a single work cost nothing |
| Crossref | `https://api.crossref.org/` | none; a contact address in `CROSSREF_MAILTO` is sent as `mailto` | metadata usable for any purpose (some abstracts are the publisher's); SAJHA keeps to 3 requests a second |
| arXiv | `https://export.arxiv.org/api/query` | none | metadata CC0; e-prints may not be stored or served, so results carry links to the abstract pages only; one request every 3 seconds across all machines |

Nothing is bought (Open Data Tools §6). Every result carries a `source` field. Every request goes
through the outbound fetch guard and HTTP proxy (`sajha/core/outbound.py`).

## Rate limits and cache

- **Throttles in the state store**, shared by every worker when the state store is `redis` or
  `database` ([Scaling and State](../../architecture/Scaling%20and%20State.md)):
  `opendata:openalex:requests` (10 a second), `opendata:crossref:requests` (3 a second) and
  `opendata:arxiv:requests` (1 every 3 seconds; a call waits up to 30 seconds for the slot). arXiv also
  refuses a network for a while on its own (on 2026-10-12 it answered 429 "Rate exceeded." for about an
  hour); the tool reports that as a rate-limit error.
- **OpenAlex budget.** The OpenAlex results carry `budget` (`cost_usd` of the call, `remaining_usd` of the
  day's budget, as OpenAlex reports them, and `keyed`). The budget is per key, or per IP without one, so the
  whole organisation shares it behind one egress IP.
- **Cache.** Each tool config sets `cache_ttl` (a day), so a repeated call is answered from the tool
  result cache.

## Conventions

- **Filter first.** `research_search_works` matches words in the title and abstract with OpenAlex's
  `title_and_abstract.search` filter; `full_text_search: true` uses OpenAlex's full search instead.
- **Identifiers.** Works are identified by DOI (`10.xxxx/...`; a `doi.org` URL is accepted). OpenAlex
  ids (`W...`) work in `research_get_work`.
- **arXiv queries.** Every word in `query` must appear (`all:` fields joined by AND); `category` is an
  arXiv category such as `q-fin.RM` (risk management), `q-fin.PR` (pricing) or `stat.ML`.
- **Limits.** `total` is the source's count and `truncated: true` says more rows exist.

## Examples

```json
{"tool": "research_search_works", "arguments": {"query": "counterparty credit risk", "from_year": 2020, "sort": "cited_by_count", "limit": 5}}
```

```json
{"tool": "research_arxiv_search", "arguments": {"query": "credit valuation adjustment", "category": "q-fin.RM", "sort": "submitted"}}
```

## Testing

`tests/test_open_data_p3.py` plays back responses recorded live (`tests/fixtures/open_data/research_*.json`)
and checks the filter, the key, `mailto` and the throttles, so the suite never calls a live service. Each
tool has a probe case and a cassette in `config/tool_tests/`. The live tool check is
`python -m sajha.quality check --folder research`.
