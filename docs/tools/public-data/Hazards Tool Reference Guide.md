# Hazards Tool Reference Guide

The hazards tools (prefix `hazards_`, tool folder `config/tools/hazards/`, implementation
`sajha/tools/impl/hazards_tools.py`) answer operational-risk and physical-climate-risk questions:
earthquakes from the U.S. Geological Survey and satellite fire detections from NASA FIRMS. The live
catalog (`tools/list`, or the Tools page) is authoritative for the tools and their parameters; the
table below is generated from the tool configs.

Why these tools exist, and on what terms, is in
[Open Data Tools](../../architecture/Open%20Data%20Tools.md).

---

## Sources and terms

| Source | Endpoint | Key | Terms |
|---|---|---|---|
| USGS earthquakes | `https://earthquake.usgs.gov/fdsnws/event/1/query` (FDSN event service) and the GeoJSON summary feeds | none | public domain; credit "U.S. Geological Survey" |
| NASA FIRMS | `https://firms.modaps.eosdis.nasa.gov/api/area/csv/{MAP_KEY}/{source}/{area}/{days}` | a free MAP_KEY in the environment variable `FIRMS_MAP_KEY` | NASA open data, no use restriction; NASA material may not imply NASA's endorsement; 5,000 transactions per 10 minutes per key |

Every result carries a `source` field. Every request goes through the outbound fetch guard and HTTP
proxy (`sajha/core/outbound.py`), and each tool config sets `cache_ttl`.

Not offered:

- **GDACS disaster alerts.** GDACS's terms of use (March 2025) grant no licence, and say alerts are
  automatic and must not be used for decisions without confirmation. The owner keeps it off until
  legal approves (Open Data Tools §6), so no tool ships for it.
- **Weather.** Open-Meteo's free API is for non-commercial use only.

## Conventions

- **Dates** are `YYYY-MM-DD` in UTC; `to` is inclusive. Times in results are ISO 8601 UTC.
- **Places.** A bounding box is `[west, south, east, north]` in degrees. `hazards_earthquakes` also
  takes a point (`latitude`, `longitude`) and `radius_km`.
- **Units.** Magnitude is on the scale named by `magnitude_type`; depth in kilometres; `alert` is the
  USGS PAGER level (green, yellow, orange, red); fire radiative power `frp_mw` in megawatts and
  brightness temperature `brightness_k` in kelvin. Each result states its units.
- **FIRMS confidence** is `low`, `nominal` or `high` for VIIRS and a percent for MODIS; `min_confidence`
  maps the words to 0, 30 and 80 percent for MODIS.
- **FIRMS without a key.** `hazards_active_fires` makes no request and says that `FIRMS_MAP_KEY` is not
  set; the live tool check reports it as `not_configured`. FIRMS puts the key in the URL path, so a
  cassette recorded with a real key would hold it: do not record one for this tool (it ships with none).

## Examples

```json
{"tool": "hazards_earthquakes", "arguments": {"latitude": 35.68, "longitude": 139.69, "radius_km": 300, "from": "2026-09-01", "to": "2026-09-30", "min_magnitude": 4, "order": "magnitude"}}
```

```json
{"tool": "hazards_active_fires", "arguments": {"bbox": [-125, 32, -114, 42], "days": 2, "min_confidence": "nominal"}}
```

## Testing

`tests/test_open_data_p3.py` plays back responses recorded live (`tests/fixtures/open_data/hazards_*.json`)
and parses a FIRMS CSV in FIRMS's documented column layout, so the suite never calls USGS or FIRMS. The
earthquake tools have probe cases and cassettes in `config/tool_tests/`. The live tool check is
`python -m sajha.quality check --folder hazards`.
