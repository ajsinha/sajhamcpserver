## Overview

The GLEIF tools (prefix `gleif_`, folder `config/tools/gleif/`) read the Global Legal Entity
Identifier Foundation's LEI records: who an entity is, where it is registered, which entity
consolidates it, which entities it consolidates, and which ISINs it has issued. They give the
counterparty exposure report its hierarchy and sit beside `edgar_company_search` (SEC filers) and
`wikidata_company_identifiers` (an LEI from a company name). Implementation:
`sajha/tools/impl/gleif_tools.py`. The live catalog in the app (Tools page, or `tools/list`) is
authoritative.

---

## Data Source and Terms

- **API:** the GLEIF JSON:API at `https://api.gleif.org/api/v1/`. No API key.
- **Terms:** LEI data is CC0 ([LEI Data Terms of Use](https://www.gleif.org/en/meta/lei-data-terms-of-use));
  GLEIF's name and logo imply no endorsement. Every result carries a `source` field.
- **Fetches** go through the outbound fetch guard and the HTTP proxy (`sajha/core/outbound.py`),
  and only to the GLEIF base URL.
- **Domain description:** `config/tools/gleif/domain.txt` (LEI format, countries, statuses).

## Parents and Reporting Exceptions

GLEIF records accounting-consolidation parents at two levels, direct and ultimate.
`gleif_parents` returns each level with a `status`:

| Status | Meaning | Extra field |
|---|---|---|
| `reported` | The entity reported a parent that has an LEI | `parent` (LEI, legal name, country, statuses) |
| `reporting_exception` | The entity filed a reason for not reporting one (for example `NATURAL_PERSONS`, `NON_CONSOLIDATING`, `NO_KNOWN_PERSON`, `NON_PUBLIC`) | `exception` (category, reason, reference) |
| `not_applicable` | GLEIF answers 404 for both the parent and the exception | none |

A 404 on a parent relationship is therefore not an error. An LEI that does not exist is an error
(`No LEI record for ...`).

`gleif_children` lists the entities that report this LEI as their direct or ultimate parent, a page
at a time (`limit`, `page`; `total` and `more` say how many remain).

## Searching by Name

`gleif_search` first asks for records whose legal or other names contain the words of `name`
(`filter[entity.names]`), with the optional `country` (legal address, ISO 3166 alpha-2) and
`status` (`ACTIVE`, `INACTIVE`) filters. When nothing matches, it falls back to GLEIF's fuzzy
completion (`fuzzycompletions` with `field=fulltext`) and fetches the records it names;
`matched_by` says which path answered. On 2026-10-11 the fuzzy completion endpoint answered an
empty list for every query tried, so a misspelt name usually finds nothing: try fewer words, or the
legal name in its local language.

## Calling the Tools

Every tool can be called over MCP (a `tools/call` request on `POST /mcp`) or over the REST API
(`POST /api/tools/execute`); see the [MCP Protocol Guide](../../protocol/MCP%20Protocol%20Guide.md)
and the [API Reference](../../protocol/API%20Reference.md).

```json
{"jsonrpc": "2.0", "id": 1, "method": "tools/call",
 "params": {"name": "gleif_parents", "arguments": {"lei": "529900SS7ZWCX82U3W60"}}}
```

## Errors

| Situation | Result |
|---|---|
| `lei` is not 20 characters (18 letters or digits, then 2 digits) | Argument error |
| Unknown LEI, or an ISIN with no LEI | Tool error naming the identifier |
| No parent and no exception | `status: not_applicable` (not an error) |
| GLEIF unreachable, refused by the outbound guard, or HTTP 5xx | Tool error with the reason |
