# US Spending Tool Reference Guide

The US spending tools (tool folder `config/tools/us_spending/`, implementation
`sajha/tools/impl/us_spending_tools.py`) read US federal spending from USAspending.gov (prefix
`usaspending_`) and the data.gov catalogue of open datasets (prefix `datagov_`). The live catalog
(`tools/list`, or the Tools page) is authoritative for the tools and their parameters; the table below
is generated from the tool configs.

Why these tools exist, and on what terms, is in
[Open Data Tools](../../architecture/Open%20Data%20Tools.md).

---

## Sources and terms

| Source | Endpoint | Key | Terms |
|---|---|---|---|
| USAspending | `https://api.usaspending.gov/api/v2/` (`search/spending_by_award`, `search/spending_by_category/{category}`, `search/spending_over_time`, `recipient`) | none | US government work; no published limit |
| data.gov catalogue | `https://catalog.data.gov/search` and `https://catalog.data.gov/api/dataset/{slug_or_id}` (OpenAPI "Datagov Catalog" 0.1.0 at `/openapi.json`); the old CKAN API at `/api/3` answers 404 | none | metadata public domain; each dataset carries its own licence (`license` in `datagov_dataset`) |

Every result carries a `source` field. Every request goes through the outbound fetch guard and HTTP
proxy (`sajha/core/outbound.py`), and each tool config sets `cache_ttl` (an hour).

## Conventions

- **Periods.** `from` and `to` are action dates (`YYYY-MM-DD`); without them, the current US federal
  fiscal year to today. USAspending searches start on 2007-10-01. Fiscal years run October to
  September (`2026` is 2025-10-01 to 2026-09-30); a month in `usaspending_over_time` is the fiscal month
  (`M01` is October).
- **Award groups.** `award_types` takes `contracts`, `idvs` (indefinite delivery vehicles), `grants`,
  `direct_payments`, `loans` and `other`. USAspending lists one group at a time: contracts, IDVs, loans,
  or assistance (grants, direct payments, other together). Loans are reported at face value.
- **Units.** US dollars obligated. Each result states its units.
- **Recipients.** `usaspending_recipient` with `name` lists matching recipients, parents first by amount;
  with `id` (a UUID with `-P` parent, `-C` child or `-R` recipient) it reads the profile.
- **data.gov.** `organization` is a catalogue slug (for example `cfpb`, `census`, `noaa-gov`); `after` is
  the cursor for the next page. The new catalogue API is undocumented beyond its OpenAPI file, so
  `tests/test_open_data_p3.py` pins the shape the tools read.

## Examples

```json
{"tool": "usaspending_awards", "arguments": {"keywords": ["cybersecurity"], "agency": "Department of Defense", "from": "2025-10-01", "to": "2026-09-30", "limit": 10}}
```

```json
{"tool": "datagov_search", "arguments": {"query": "consumer complaints", "organization": "cfpb"}}
```

## Testing

`tests/test_open_data_p3.py` plays back responses recorded live (`tests/fixtures/open_data/usaspending_*.json`,
`datagov_*.json`), so the suite never calls either service. Each tool has a probe case and a cassette in
`config/tool_tests/`. The live tool check is `python -m sajha.quality check --folder us_spending`.
